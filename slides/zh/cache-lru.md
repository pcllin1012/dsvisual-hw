## LRU 快取

LRU(Least Recently Used)快取在容量上限內保留最近使用的項目;以雜湊表搭配雙向連結串列,讓 get 與 put 都是 $O(1)$,並在滿載時淘汰最久未使用的項目。

---

## 核心概念

雙向連結串列維護使用順序:表頭是最近使用(MRU),表尾是最久未使用(LRU);雜湊表把每個鍵直接對應到串列節點,免去線性搜尋。

- 每次存取(命中或新增)都把該節點移到表頭。
- 容量滿時淘汰表尾節點,並從雜湊表移除其鍵。
- 雙向串列讓「移到表頭」與「移除任一節點」都是 $O(1)$。

---

## 運作流程

1. get(key):命中則回傳值並把節點移到表頭;未命中回傳 -1。
2. put(key, val):鍵已存在則更新值並移到表頭。
3. put 新鍵:若已滿先淘汰表尾,再把新節點插入表頭。

## 複雜度分析

| 操作 | 時間 | 空間 |
| --- | --- | --- |
| get | $O(1)$ | $O(n)$ |
| put | $O(1)$ | $O(n)$ |
| 淘汰 | $O(1)$ | $O(1)$ |

$$T_{get}(n) = T_{put}(n) = O(1)$$

雜湊表定位加上雙向串列的常數時間指標操作。

---

## 程式碼

```cpp
int get(int key) {
    auto it = index.find(key);
    if (it == index.end()) return -1;
    items.splice(items.begin(), items, it->second);  // move to MRU
    return it->second->second;
}

void put(int key, int val) {
    auto it = index.find(key);
    if (it != index.end()) {                 // hit: update + promote
        it->second->second = val;
        items.splice(items.begin(), items, it->second);
        return;
    }
    if (items.size() == cap) {               // full: evict LRU (tail)
        index.erase(items.back().first);
        items.pop_back();
    }
    items.push_front({key, val});            // insert as MRU (head)
    index[key] = items.begin();
}
```

---

## 優缺點與使用時機

- 優點:get/put 皆 $O(1)$,實作直觀,淘汰策略貼合時間區域性。
- 缺點:每項需雜湊表項 + 串列節點的額外記憶體;掃描型存取容易顛簸。
- 適用:資料庫/頁面快取、CPU 快取近似、需固定容量且偏好近期資料的場景。

---

## 小結

- 雜湊表 + 雙向連結串列 = $O(1)$ 的 get 與 put。
- 表頭為 MRU、表尾為 LRU;每次存取都移到表頭。
- 容量滿時淘汰表尾(最久未使用)。
